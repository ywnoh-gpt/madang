# 마당 독립 HTML 기록장

Google Apps Script나 스프레드시트 없이 물건 입력·목록·원본 검토·예측 성과를 한 앱에서 사용합니다. 기존 Apps Script 버전은 보존되어 있습니다.

[물건 목록 미리보기](images/html-records.png) · [입력 화면](images/html-editor.png) · [모바일 화면](images/html-mobile.png)

## 처음 실행

웹주소를 고정해서 쓰는 GitHub Pages 방식을 권장합니다. 기록은 주소별로 구분되므로, 개발용 localhost와 GitHub Pages에서 보이는 기록은 서로 다릅니다. 옮길 때 JSON 백업·가져오기를 사용하세요.

### GitHub Pages에 게시

1. 저장소의 **Settings → Pages**를 엽니다: <https://github.com/ywnoh-gpt/madang/settings/pages>
2. **Build and deployment → Source**에서 **Deploy from a branch**를 선택합니다.
3. Branch는 **`feat/standalone-html-journal`**, Folder는 **`/ (root)`**를 선택하고 **Save**를 누릅니다. 나중에 이 변경을 main으로 병합한다면 main으로 변경할 수 있습니다.
4. GitHub가 게시 완료를 표시하면 안내된 주소를 엽니다. 기본 예상 주소는 `https://ywnoh-gpt.github.io/madang/`이며, 실제 게시가 끝나기 전에는 사용할 수 없습니다.

이 설정으로 프로그램 화면과 코드가 공개됩니다. 개인 기록·API 키가 GitHub에 올라가는 기능은 없습니다. 같은 PC의 같은 브라우저 프로필을 사용하는 사람은 그 브라우저에 저장한 기록을 볼 수 있습니다. 로그인 기능이나 원격 동기화는 제공하지 않습니다.

### 개발 환경에서 실행

저장소 루트에서 다음을 실행합니다.

```sh
node tools/build_web.cjs
python3 -m http.server 8000 --bind 127.0.0.1
```

`http://localhost:8000`을 Chrome/Edge에서 엽니다. 서버는 정적 파일만 제공하고 개인 기록이나 API 키를 받지 않습니다. 포트·브라우저·주소를 바꾸면 다른 저장 공간을 사용하므로 백업으로 이전하세요. 이 명령은 로컬 개발용이며 인터넷 공개 서버로 사용하지 마세요.

루트의 `index.html`에는 CSS·JavaScript가 모두 포함돼 있습니다. 파일을 직접 여는 방식은 브라우저 정책과 로컬 파일 저장 지원에 따라 달라집니다. 관리형 브라우저가 파일 접근을 차단할 수 있으며 이 환경에서는 로컬 HTTP 방식으로 검증했습니다. GitHub의 소스 보기나 raw 링크는 실행 화면이 아닙니다.

## AI 연결

1. **AI 연결 설정**을 엽니다.
2. 본인의 Gemini API 키를 입력합니다. 키는 창의 메모리에만 보관되므로 새로고침·종료 후 다시 입력해야 합니다. 기존 Apps Script에 저장한 키를 자동으로 읽을 수는 없습니다.
3. 기존 사용자 환경에서 동작한 **`gemini-flash-lite-latest`**가 기본값입니다. 모델 사용 가능 여부는 계정과 시점에 따라 달라집니다. 필요하면 **모델 목록 조회** 후 문서용 모델을 선택하고 저장합니다.
4. **실제 연결 점검**으로 해당 모델의 생성 응답을 확인합니다. 모델 목록 조회 성공만으로 생성 요청 성공을 보장하지 않습니다.

브라우저에서 Google `generativelanguage.googleapis.com`으로 직접 요청합니다. 키는 인증 헤더로 보내고 URL·브라우저 저장소·백업·GitHub에는 넣지 않습니다. 이 방식은 본인이 키를 넣어 쓰는 개인용 앱입니다. 배포자의 공용 키를 HTML에 넣어 제공하지 마세요.

API 키에 HTTP 리퍼러 제한을 걸었다면 Pages 주소 또는 로컬 개발 주소를 허용해야 합니다. 연결 오류는 네트워크·브라우저·키 제한을 확인하세요. HTTP 503은 Google 혼잡일 수 있으며 자동 재시도하지 않습니다. 60초에 브라우저 대기를 중단하더라도 Google 서버의 처리가 취소됐다는 뜻은 아닙니다.

수동 입력·저장·복기·백업에는 API 키가 필요 없습니다.

## 기록 순서

1. **새 물건 기록**에서 같은 물건·같은 기일의 캡처 또는 PDF를 1~3개 올립니다. 이미지는 5MB, PDF는 8MB, 전체는 12MB까지입니다.
2. 필요하면 **AI로 내용 읽기**를 누릅니다. 이 동작 때 선택한 파일을 Google에 전송합니다. AI는 사실 항목만 읽고 나의 예측값은 채우지 않습니다. 별도로 입력한 예측값도 유지합니다.
3. 원본 미리보기와 인식값을 대조하고 수정합니다. 노란 항목은 불확실하거나 자료에서 찾지 못한 값입니다. 자료끼리 충돌하는 경우 파일을 나눠 확인하세요.
4. 나의 예측·모의 입찰·시세·비용·목표 이익을 입력합니다. 상한가는 자동 계산합니다.
5. 원본 대조 여부와 결과 확인 전 예측 여부를 확인하고 저장합니다. 원본 파일 보관을 해제하면 파일명·해시·AI 인식값만 보관합니다.
6. 결과가 나오면 목록의 **상세·복기**에서 결과·낙찰가·입찰자 수·복기를 추가합니다. 최초 예측은 수정하지 않으며 결과 수정 전 값도 보존합니다.
7. 유찰 뒤 다음 기일은 **다음 기일 기록**으로 새 행을 만듭니다. 새 기일·최저가·유찰 횟수를 확인하고 예측을 새로 입력하세요.

임시 입력은 브라우저에 자동 저장됩니다. 복원 후 원본 대조를 다시 확인해야 저장할 수 있습니다. 목록 검색·결과 필터와 관계없이 성과 카드는 전체 기록을 기준으로 계산합니다.

### 권장 자료

- 경매 물건 상세 화면 캡처: 법원·사건·물건번호·기일·감정가·최저가 확인용.
- 매각물건명세서: 점유·매각 조건 등 상세 검토용. 다음 기일과 최저가가 빠질 수 있습니다.
- 등기부등본: 권리관계 검토용. 단독으로 경매 기본 정보를 모두 채우기 어렵습니다.
- 감정평가서·현황조사서: 면적·유형·현황 등 보완용.

법적 결론·명도 비용·시세·이익을 AI가 확정하지 않습니다. 상세 메모와 출처 링크도 함께 남기세요.

## 백업·이전

**백업 저장**의 JSON은 기록·보관 원본·원본 AI 인식·변경 이력을 포함하며 키나 임시 작성 내용은 포함하지 않습니다. 중요한 작업 뒤 내려받아 안전한 곳에 보관하세요. 사이트 데이터 삭제나 시크릿 모드 종료 등으로 브라우저 기록이 사라질 수 있습니다. 저장 공간 유지 요청도 수동 데이터 삭제를 막지는 못합니다.

**가져오기**는 기존 기록을 덮어쓰지 않고 병합합니다. 동일 물건·기일의 필드 내용이 같으면 건너뛰고, 다르면 전체 가져오기를 취소합니다. 최신 백업으로 옛 기록을 자동 덮어쓰는 도구는 아닙니다. 충돌 시 복기 내용을 확인하고 별도로 기록하세요.

기존 Google 시트의 **마당 기록** 탭에서 **파일 → 다운로드 → 쉼표로 구분된 값(.csv)**으로 저장한 후 가져오세요. 기존 열 이름을 사용하고 첫 줄의 버전 표식이 있어도 처리합니다. 원본 예측 여부는 `결과 확인 전 예측` 열의 TRUE/참 값만 인정하며 임의로 추정하지 않습니다. CSV에는 원본 파일·AI 인식·Apps Script 변경 이력이 포함되지 않으므로 기존 시트를 보관하세요. CSV 내보내기는 표 확인용이며 완전한 백업은 JSON을 사용합니다.

브라우저 저장·파일 백업은 사용자가 직접 고칠 수 있으므로 예측의 사전 작성 시점을 제3자가 인증하는 기능은 아닙니다.

## 개발·검증

개발 소스는 `web/`, 단일 실행 파일은 빌드한 루트 `index.html`입니다. 화면 수정 후 `node tools/build_web.cjs`를 실행해 결과도 커밋하세요. UI 라이브러리·외부 폰트·CDN에 의존하지 않습니다.

```sh
node tools/build_web.cjs
node --test tests/web_core.test.cjs
.venv/bin/python tests/web_browser.py
```

브라우저 검증은 Chromium과 IndexedDB를 실제로 사용합니다. Gemini 응답은 테스트 대역으로 교체하므로 실제 Google 연결 성공을 뜻하지 않습니다. 이 전환 버전에서 사용자의 실제 키로 호출하거나 기존 Google 기록을 읽지 않았습니다. 사용자의 기존 Apps Script에서는 API·PDF·시트 점검 통과를 확인했으나 별도 브라우저의 키 제한·접속 환경은 앱의 실제 연결 점검으로 확인해야 합니다.
