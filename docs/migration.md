# 기존 기록 이전

1. 기존 Google 시트의 ‘마당 기록’ 탭에서 CSV를 내보내거나, 이전 HTML 앱의 **CSV 내보내기**를 사용합니다. 기존 앱의 JSON 백업과 원본 파일도 보관하세요.
2. 새 앱에 로그인해 **물건 기록 → CSV 가져오기**를 선택합니다. 한 번에 500행, 10MB까지 지원합니다.
3. 행 수를 확인하고 가져옵니다. 원본 CSV 행을 `import_context`와 최초 감사 이력에 보존합니다. 새 저장 시각은 DB 서버 시각이며 과거의 예측 시각을 인증한 값은 아닙니다.
4. 같은 법원·사건번호·물건번호·매각기일은 덮어쓰지 않고 건너뜁니다. 내용이 달라도 기존 기록을 변경하지 않으므로 중복·누락 수와 주요 금액을 비교하세요.
5. 한 행이라도 DB 검증에 실패하면 해당 가져오기는 전체 취소됩니다. 원본 CSV를 보존하고 잘못된 날짜·금액을 확인해 다시 가져오세요.
6. 원본 PDF/캡처와 과거 AI 인식·수정 이력은 CSV로 이동하지 않습니다. 새 물건 상세에서 원본을 올려 추가 분석하거나 기존 백업을 함께 보관하세요.

`결과 확인 전 예측` 열은 TRUE/참만 인정하며 다른 값은 사전 예측으로 추정하지 않습니다. 유찰 뒤 다음 매각기일은 새 행입니다. 원본 예측은 저장 후 수정할 수 없고 결과·복기만 수정됩니다. 잘못 옮긴 물건 정보는 원본을 확인하고 운영자와 DB 이관을 검토하세요. 데이터를 삭제하는 자동 정리 기능은 없습니다.

이전 시트·Apps Script·브라우저 IndexedDB는 새 코드가 접근하거나 삭제하지 않습니다. 기존 버전의 파일을 현재 Git 브랜치에서 제거했어도 이전 커밋과 브랜치에서 확인할 수 있습니다. 엑셀 템플릿과 생성 스크립트는 보존했습니다.

새 앱 JSON 백업은 기록·원본 메타데이터·분석·검토본·거래·시뮬레이션·감사 이력을 포함합니다. 바이너리는 Supabase Storage에 따로 있으며 JSON에 포함하지 않습니다. 운영 DB·Storage 백업 정책은 Supabase 프로젝트에서도 별도로 설정하세요.
