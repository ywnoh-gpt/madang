# madang 모의 입찰 기록장

WealthOS와 분리된 부동산 경매 학습 프로젝트입니다. 20~30건의 사전 예측을 기록한 뒤 필요한 도구를 결정합니다.

## 사용

1. `templates/madang-auction-journal-50.xlsx`(50회차, 약 25KB)를 **복사해** 개인 기록 파일을 만드세요. 300회차 버전은 `templates/madang-auction-journal.xlsx`입니다.
2. ‘사용 안내’를 읽고 ‘물건 기록’ 파란 입력 칸에 작성하세요. 회색 칸은 수식입니다.
3. `docs/property-note.md`를 물건별로 복제하거나 Google Docs 등에 붙여 넣고 상세 메모 링크를 기록하세요.
4. 결과 확인 전에 예측을 확정하세요. 원본 예측을 덮어쓰지 말고 수정은 ‘예측 변경 이력’에 추가하세요. 자동 변경 추적은 없으므로 파일 버전 기록을 함께 사용하세요.
5. 결과를 입력하고 ‘성과 요약’과 복기 메모를 검토하세요. 동일 물건의 다음 매각기일은 새 행입니다.

시트는 사용 안내, 물건 기록(50회차 또는 300회차), 성과 요약, 예측 변경 이력으로 구성됩니다. 예시 데이터는 없습니다. Google Drive에 업로드하여 Google 스프레드시트로 열 수도 있습니다. 변환 후 날짜·수식·드롭다운을 확인하세요.

평가 대상은 식별값 완비·중복 없는 낙찰 회차로, 양수인 예상/실제 낙찰가와 예상 작성일≤매각기일이 필요합니다. 같은 날 결과 전 기록인지는 사용자가 확인해야 합니다. 중복 행은 모두 평가에서 빠집니다. 평균 절대 오차율로 정확도를, 평균 예측 오차율로 방향 편향을 봅니다. 가상 입찰가의 실제 낙찰가 초과는 낙찰 보장이 아니며, 동액은 별도로 표시합니다. 수익성은 상한가 비교로 따로 판단합니다.

## 생성과 검증

```bash
cd /workspace/madang
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/create_workbook.py --rows 50 --output /tmp/my-auction-journal.xlsx
.venv/bin/python -m unittest discover -s tests -v
```

생성기는 기존 파일이 있으면 중단하여 입력 자료를 보호합니다. 기본 경로의 배포 템플릿도 덮어쓰지 않습니다. 새 경로로 생성하여 검토하세요. 별도 서버·DB·API 키는 필요 없습니다.

검증: openpyxl로 파일 구조/드롭다운을 읽고 formulas 엔진으로 실제 셀 수식의 상한가, 빈 값, 양수/음수 오차, 평가 제외, 중복, 동액, 최저가 미달, 상한가 초과와 요약 집계를 테스트했습니다. Excel 또는 Google 스프레드시트 실제 앱의 재계산·화면은 검증하지 않았습니다. 수식 캐시는 없으며 파일을 여는 앱에서 재계산합니다.

크기 조정은 생성기의 `--rows 50` 또는 `--rows 30` 옵션을 사용합니다. 파일 크기가 작아도 클라우드 내부 경로(`/workspace/...`)는 다른 컴퓨터에서 직접 열 수 없습니다. GitHub에 게시된 파일 페이지에서는 Download raw file로 저장한 후 Excel에서 여세요.
