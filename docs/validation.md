브라우저 검증은 혼합 이미지/PDF → 인식값 수정 → 기존 개인 예측 유지 → 저장 → 결과 갱신 → 5% 오차 경계 집계 → 중복 거부를 확인했습니다. 320·390·1440px에서 페이지가 가로로 넘치지 않았습니다. 키 저장 테스트는 테스트용 문자열을 사용했으며 비밀번호 입력 칸이 비워지고 결과에 키가 노출되지 않는 것을 확인했습니다. 실제/모의 점검을 구분하고, 점검이 기존 기록·이력·Drive 보관 개수를 바꾸지 않는 것도 확인했습니다.

실제 키는 코드·GitHub·로그·보고서에 저장하지 않았습니다. 사용자가 Apps Script에 등록한 키를 여기서 읽거나 원격 실행한 것은 아닙니다. 모의 응답의 성공을 실제 API 성공으로 간주하지 않습니다. 앱의 **등록 키·모델 조회 / API 응답 / PDF 인식 / 시트 저장** 버튼에서 각 단계를 별도로 실행해 확인해야 합니다.

시간 초과에 대응해 연속 전체 점검과 자동 재시도를 제거했습니다. 한 버튼이 외부 요청을 한 번만 만드는지, 모델 목록 성공을 생성 성공으로 간주하지 않는지, 요청 전에 진행 단계가 저장되는지, 종료 기록이 없는 스냅샷이 성공으로 표시되지 않는지 확인했습니다. 시트 저장 점검은 키·API 호출과 독립적으로 실행되며 임시 탭의 쓰기·읽기·정리를 확인합니다. 모델 선택은 조회된 목록에서 명시적으로 저장할 때만 바뀝니다.

사용자가 보고한 Google 최대 실행 시간 초과는 원격 계정에서 직접 재현하거나 해결 확인하지 못했습니다. 단일 UrlFetch 요청의 강제 타임아웃·취소를 보장하는 변경은 아닙니다. 네트워크가 멈춘 실제 상황에서의 소요 시간은 Google 계정에서 개별 점검으로 확인해야 합니다. 자동 검증의 Google 서비스와 Gemini 응답은 모의이며, 기존 사용자 키로 실제 호출을 수행한 것은 아닙니다.
