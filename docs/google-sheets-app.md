# 캡처·PDF를 읽는 마당 기록장

Google 스프레드시트에 연결하는 개인용 Apps Script 앱입니다. 캡처와 PDF를 올리고, Gemini가 읽은 내용을 원본과 대조·수정한 뒤 시트에 저장합니다. 기존 엑셀 파일은 별도로 유지합니다.

## 처음 설치하기

한 번만 연결하면 이후에는 스프레드시트의 메뉴에서 엽니다. Google 계정의 승인과 Gemini API 키 입력은 본인이 해야 합니다. 이 저장소에는 키가 없습니다.

1. [새 Google 스프레드시트](https://sheets.new)를 만들고 이름을 `마당 모의 입찰 기록장`으로 정합니다.
2. **확장 프로그램 → Apps Script**를 엽니다.
3. 이 저장소의 [dist/Madang.gs](../dist/Madang.gs)를 열어 **Raw**에서 전체 내용을 복사합니다.
4. Apps Script의 `Code.gs` 기본 내용을 지우고 복사한 내용을 붙여 넣은 뒤 저장합니다. HTML도 포함된 단일 파일이므로 다른 파일을 추가하지 않아도 됩니다.
5. 실행할 함수로 **setupJournal**을 선택해 실행하고, 본인이 만든 이 프로젝트에 권한을 승인합니다. 전용 탭 3개를 만들고 웹앱에서 사용할 시트 ID를 기억합니다.
6. 스프레드시트로 돌아와 새로고침합니다. 상단 **마당 기록장 → Gemini API 키 설정**에서 [Google AI Studio](https://aistudio.google.com/apikey)의 API 키를 입력합니다. 키를 채팅·시트 셀·GitHub에 적지 마세요.
7. **마당 기록장 → 기록장 열기**를 누릅니다. 시트 오른쪽에 입력 화면이 열리고, 실제 시트는 그 옆에서 바로 확인할 수 있습니다.

API 키는 스크립트 속성 `GEMINI_API_KEY`에 보관합니다. 스크립트 편집 권한이 있는 사람은 키를 볼 수 있으므로 개인용 시트로 사용하세요. 기본 인식 모델은 `gemini-flash-latest`이고 **마당 기록장 → 인식 모델 설정**에서 계정에서 사용 가능한 모델로 바꿀 수 있습니다. API 사용량·비용·모델 제공 여부는 Google 계정의 설정에 따릅니다.

앱은 Sheets 읽기·쓰기, 시트의 메뉴·화면 표시, Gemini로 자료 전송, 선택한 원본의 Drive 보관을 사용합니다. 단일 파일 설치에서는 Apps Script가 사용 코드에 따라 권한을 요청합니다. 소스 프로젝트를 그대로 올릴 때는 `apps-script/appsscript.json`에 동일한 권한과 서울 시간대가 선언되어 있습니다.

## 넓은 화면으로 사용하기 (선택)

시트 옆의 사이드바 대신 넓은 화면을 원하면, 위의 최초 시트 준비를 마친 뒤 Apps Script에서 **배포 → 새 배포 → 웹 앱**을 선택합니다.

- 실행 사용자: **나**
- 액세스할 수 있는 사용자: **나만**

생성된 웹앱 URL을 북마크하세요. 왼쪽에서 원본 자료를 보고 오른쪽에서 수정하며 아래에서 최근 기록을 확인할 수 있습니다. 저장·결과 수정 직후 기록과 요약을 갱신하고, 열려 있는 화면은 15초마다 시트를 다시 읽습니다. 실제 Google 시트는 상단 **시트 열기**로 엽니다. 이 화면은 Google 시트 편집기를 임베드한 화면이 아니라 해당 시트의 데이터를 표시하는 화면입니다.

코드를 고친 뒤에는 기존 웹앱의 배포 관리에서 새 버전으로 업데이트해야 합니다. 사이드바는 저장 후 다시 열면 됩니다.

## 어떤 자료가 좋을까요?

| 자료 | 쓰임 | 확인할 점 |
|---|---|---|
| 마당·법원의 물건 기본정보 캡처 또는 PDF | 사건번호·물건번호·기일·감정가·최저가 | 처음 기록할 때 가장 유용합니다. 결과가 보이는 화면으로 사전 예측을 만들지 마세요. |
| 매각물건명세서 | 물건 식별·점유·임대차 등 원문 확인 | 기본정보 화면과 함께 올리는 것을 권합니다. 최신 작성일·정정 여부를 확인하세요. |
| 감정평가서 | 주소·면적·감정가 근거 | 감정 당시 가격과 현재 시세는 구분하세요. 긴 문서는 필요한 페이지만 올리세요. |
| 현황조사서 | 점유·현장 상태 확인 | 작성 시점과 실제 현황은 다를 수 있습니다. |
| 등기부등본 | 등기 내용과 물건 식별 보충 | 불필요한 개인식별정보를 가리고 최신 문서인지 확인하세요. |

처음에는 **기본정보 화면 + 매각물건명세서**로 시작하고 필요할 때 다른 자료를 추가하세요. 등기부만으로 최저가·기일·시장 예상 낙찰가를 채울 수는 없습니다. 현재 버전은 공통 물건 정보를 정리하며 임차인별 표나 등기 권리별 분석표까지 자동 생성하지는 않습니다. 권리관계의 법적 결론은 만들지 않습니다. 자세한 판단은 상세 메모 링크에 남기세요.

같은 물건의 자료를 최대 3개까지 함께 올릴 수 있습니다. PNG·JPG·WebP는 파일당 5MiB, PDF는 파일당 8MiB, 합계 12MiB까지입니다. HWP·Word는 PDF로 저장해 올리세요. 암호가 있는 PDF는 본인 컴퓨터에서 해제하고 필요한 페이지만 추출하세요. 서로 다른 물건이나 매각기일은 나눠 기록합니다.

## 사용 흐름

1. 이미지 붙여넣기·드래그·파일 선택으로 자료를 올립니다. 자료 종류를 고르면 인식에 함께 전달합니다. **AI로 정보 읽기**를 누를 때 Gemini API로 전송합니다.
2. AI가 읽은 물건 정보를 원본과 대조합니다. 읽지 못한 값과 신뢰도가 낮거나 불확실한 값은 별도로 표시됩니다. 문서끼리 충돌한 값은 비워 두도록 요청하며, 불확실한 원문은 알림에 표시합니다. AI가 이를 항상 정확히 지키는 것은 아니므로 검토는 필수입니다.
3. **예상 낙찰가·가상 입찰가·시세·비용·목표 이익은 직접 입력**합니다. 인식을 다시 실행해도 작성 중인 예측·비용·판단 근거는 유지합니다.
4. 확인 체크 후 저장합니다. 원본 자료를 Drive에 보관할지는 별도로 선택합니다. 선택하면 개인 폴더에 저장하며 공개 공유를 설정하지 않습니다. 선택하지 않으면 파일 자체를 보관하지 않고 이름·해시와 인식·수정 내용만 남깁니다.
5. 결과가 나오면 기록의 **결과·복기**에서 실제 낙찰가·입찰자 수와 복기 메모를 입력합니다. 기록에 보관된 원본 자료 링크도 여기서 열 수 있습니다.

키 연결 전에도 **직접 입력**으로 기록할 수 있습니다. 저장 전에 ‘인식값 수정 이유’를 남기면 LLM 원본과 사용자 수정값을 함께 복기할 수 있습니다. AI가 없는 낙찰 결과를 읽었다면 결과를 정정한 뒤 **결과 인식 오류 확인 + 수정 이유**를 남겨 사전 예측으로 저장할 수 있습니다.

인식 결과는 사용자별 캐시에 최대 6시간 보관하며 캐시 사정에 따라 일찍 만료될 수 있습니다. 만료 오류가 나면 같은 자료를 다시 읽으세요. 이미 입력한 개인 예측은 유지됩니다. 저장하지 않고 페이지를 닫으면 입력은 보관되지 않습니다.

## 기록과 성과의 원칙

- 법원·사건번호·물건번호·매각기일 조합당 한 행입니다. 동시 저장에도 잠금으로 중복을 확인합니다.
- 유찰 후 다음 기일은 새 행으로 추가합니다.
- 상한가 = 예상 시세 − 추가 비용 합계 − 목표 이익. 비용이 없으면 0을 명시하세요.
- 오차율 = (예상 낙찰가 − 실제 낙찰가) ÷ 실제 낙찰가. 평균 절대 오차율로 정확도를 평가합니다.
- 사전 예측 확인, 유효한 작성일과 매각기일, 양수인 예상·실제 낙찰가, 낙찰 결과가 있고 중복이 없는 기록을 평가합니다. 미래 작성일이나 기일 후 작성일은 사전 예측으로 저장하지 않습니다. 같은 날 실제로 결과를 보기 전에 작성했는지는 직접 확인합니다.
- 이미 낙찰 결과가 보이는 자료는 참고 기록으로 저장하고 정확도 집계에서 제외합니다. 시스템 저장 시각도 함께 보존하지만 사전 예측 체크는 사용자 확인이며 외부 공증 기능은 아닙니다.
- 앱은 저장된 원래 예측을 바꾸지 않고 결과 항목만 수정합니다. LLM 인식값·저장값·결과 변경 전후 값은 ‘마당 변경 이력’에 남습니다. 실패한 작업에도 ‘저장 전 보존’ 기록이 남을 수 있으며 이것만으로 최종 저장 성공을 뜻하지 않습니다.
- Google 시트에서 직접 셀을 편집하면 앱의 보호·변경 이력 경로를 거치지 않습니다. 입력과 결과 수정은 앱을 사용하세요. 직접 수정했다면 **마당 기록장 → 계산·성과 새로고침**으로 계산 열과 시트 요약을 갱신합니다. 앱의 요약은 조회할 때 전체 기록으로 다시 계산합니다.
- 가상 입찰가는 최저가·실제 낙찰가·상한가와 각각 비교합니다. 동액은 따로 표시하며 낙찰 가능성과 수익성은 따로 판단합니다.

## 개발·검증

필수 런타임은 Node.js 22 이상입니다. 서버 운영이나 npm 패키지 설치는 필요 없습니다. 소스는 `apps-script/Code.gs`, `apps-script/Index.html`이고 배포용 단일 파일은 빌드로 만듭니다.

```bash
cd /workspace/madang
node tools/build_apps_script.cjs
node --test tests/apps_script_backend.test.cjs tests/apps_script_bundle.test.cjs
```

실제 Chromium에서 UI와 Apps Script 로직을 연결한 테스트도 있습니다. Google 서비스와 Gemini 응답은 테스트용 모의 서비스입니다. 개인 자료나 실제 API 키를 사용하지 않습니다.

```bash
python -m pip install -r requirements-browser.txt
# 이미 설치된 chromium 또는 google-chrome을 자동으로 사용합니다.
# 없다면: python -m playwright install chromium
python tests/browser_smoke.py
```

검증은 혼합 PNG/PDF 업로드 → 인식값 수정 → 개인 예측 보존 → 저장 → 결과 입력 → 오차 집계 → 중복 거부 및 320/390/1440px 레이아웃을 확인합니다. 테스트 서버는 검증 중에만 루프백에서 열고 끝나면 종료합니다.

현재 실제 Google 계정의 권한 승인·시트 저장·Drive 보관·Gemini 호출은 미검증입니다. 계정 연결 후 캡처 한 건으로 먼저 실행해 금액·날짜와 실제 저장 결과를 확인하세요. 모의 테스트 통과는 실제 API 접근이나 인식 정확도를 보장하지 않습니다.

API 형식 참고: [공식 Google Gen AI SDK 구조화 출력](https://github.com/googleapis/python-genai/blob/main/README.md#json-response-schema), [Google generateContent API 스키마](https://github.com/googleapis/googleapis/blob/master/google/ai/generativelanguage/v1beta/generative_service.proto).
