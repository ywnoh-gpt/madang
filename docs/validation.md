# 검증 결과

## 독립 HTML 웹앱 · 2026-10-26 (한국 시간)

브랜치 `feat/standalone-html-journal`에서 다음을 실행했습니다.

| 검증 | 결과 | 범위 |
|---|---|---|
| `node tools/build_web.cjs` | 통과 | 약 85KB 단일 HTML, 현재 소스 포함·외부 UI 의존 없음 |
| `node --test tests/*.test.cjs` | 56개 통과 | 기존 48개 및 독립 앱 계산·이전·전송·번들 8개 |
| `.venv/bin/python tests/web_browser.py` | 8개 통과 | 실제 Chromium·IndexedDB, Gemini만 모의 |
| 이미지·PDF 미리보기 | 확인 | Chromium 기본 PDF 뷰어와 원본 새 창 링크 |
| GitHub Pages 설정 조회 | 차단됨 | `api.github.com` 요청 Forbidden, 게시 설정 변경 없음 |
| 사용자 키로 실제 브라우저 Gemini 호출 | 미실행 | 키를 클라우드에서 보유·조회하지 않음 |

실제 브라우저에서 새로고침 후 기록 보존, PDF 업로드 → AI 인식값 수정 → 원문과 최초 예측 보존, 결과 갱신 → 5% 경계 집계, 중복 거부, 다른 브라우저 프로필로 JSON 복원, 기존 시트 CSV 이전, 충돌 파일의 전체 가져오기 취소, 임시 입력 복원, 원본 파일 포함·키 미포함 백업, 새로고침 후 키 소멸을 검증했습니다. 390·768·1560px에서 모든 화면이 페이지 폭을 넘지 않았으며 수동 입력·목록·안내 이용 중 Google 요청이 발생하지 않았습니다. API 503은 한 번만 요청하고 키를 오류에 표시하지 않았습니다. 같은 IndexedDB에 겹치는 저장 요청 중 한 건만 성공하며, 다른 탭에서도 같은 기록을 읽고 중복을 거부하는 것을 확인했습니다.

Gemini 성공 응답은 테스트 대역입니다. 실제 사용자에게서는 기존 Apps Script의 API·PDF·시트 단계 모두 통과했다는 보고를 받았으나, 독립 웹앱에서의 실사용 키·HTTP 리퍼러 제한은 별도 확인이 필요합니다. Google 계정이나 기존 시트 데이터를 직접 읽지 않았습니다. 관리형 Chromium은 `file://` 탐색을 차단해 로컬 HTTP에서 검증했습니다. GitHub Pages 게시 완료 또는 실제 공개 URL 접속 성공을 주장하지 않습니다.

재실행·배포 안내는 [독립 HTML 앱 안내](html-app.md)에 있습니다.

## 이전 Apps Script 검증 기록 · 2026-10-25 (한국 시간)

아래는 브랜치 `feat/screenshot-sheets-app` 작업 당시의 기록입니다. 이후 사용자 보고로 실제 API·PDF·시트 점검 통과를 확인했습니다.

| 검증 | 결과 | 외부 연동 범위 |
|---|---|---|
| Apps Script 저장·진단·단일 파일 설치 테스트 | 48개 통과 | Google 서비스와 Gemini 응답은 모의 |
| Python API 검사 도구 및 기존 엑셀 수식 테스트 | 15개 통과 (10월 22일 검증, 해당 소스 변경 없음) | API 응답은 모의, 엑셀 수식은 별도 계산 엔진 |
| Chromium 브라우저 흐름·레이아웃·연결 설정 | 7개 통과 | 실제 UI와 Apps Script 코드 사용, Google 서비스와 Gemini 응답은 모의 |
| 합성 PDF 및 API 요청 형식 dry-run | 통과 | API 요청 없음 |
| PDF 파일의 구조·텍스트 추출 | 통과 | 로컬 `pdfinfo`·`pdftotext` 사용 |
| 클라우드의 실제 Google API 접근 | 직전 점검에서 차단됨 | 10월 22일 키 없는 접속 시 프록시 터널에서 HTTP 403 |
| 본인 Google 계정의 OAuth 승인·키 등록 | 사용자 진행 | 원격 계정 연결이 없어 여기서 직접 조회하지 않음 |
| 등록된 키로 실제 Gemini 정상 작동 | 미확인 | 사용자가 전달한 응답은 HTTP 503이며 정상 연결·키 유효성을 증명하지 않음 |

브라우저 검증은 혼합 이미지/PDF → 인식값 수정 → 기존 개인 예측 유지 → 저장 → 결과 갱신 → 5% 오차 경계 집계 → 중복 거부를 확인했습니다. 320·390·1440px에서 페이지가 가로로 넘치지 않았습니다. 키 저장 테스트는 테스트용 문자열을 사용했으며 비밀번호 입력 칸이 비워지고 결과에 키가 노출되지 않는 것을 확인했습니다. 실제/모의 점검을 구분하고, 점검이 기존 기록·이력·Drive 보관 개수를 바꾸지 않는 것도 확인했습니다.

실제 키는 코드·GitHub·로그·보고서에 저장하지 않았습니다. 사용자가 Apps Script에 등록한 키를 여기서 읽거나 원격 실행한 것은 아닙니다. 모의 응답의 성공을 실제 API 성공으로 간주하지 않습니다. 앱의 **등록 키·모델 조회 / API 응답 / PDF 인식 / 시트 저장** 버튼에서 각 단계를 별도로 실행해 확인해야 합니다.

시간 초과에 대응해 연속 전체 점검과 자동 재시도를 제거했습니다. 한 버튼이 외부 요청을 한 번만 만드는지, 모델 목록 성공을 생성 성공으로 간주하지 않는지, 요청 전에 진행 단계가 저장되는지, 종료 기록이 없는 스냅샷이 성공으로 표시되지 않는지 확인했습니다. 시트 저장 점검은 키·API 호출과 독립적으로 실행되며 임시 탭의 쓰기·읽기·정리를 확인합니다. 모델 선택은 조회된 목록에서 명시적으로 저장할 때만 바뀝니다.

사용자가 보고한 Google 최대 실행 시간 초과는 원격 계정에서 직접 재현하거나 해결 확인하지 못했습니다. 단일 UrlFetch 요청의 강제 타임아웃·취소를 보장하는 변경은 아닙니다. 네트워크가 멈춘 실제 상황에서의 소요 시간은 Google 계정에서 개별 점검으로 확인해야 합니다. 자동 검증의 Google 서비스와 Gemini 응답은 모의이며, 기존 사용자 키로 실제 호출을 수행한 것은 아닙니다.

재실행 명령은 [설치·개발 안내](google-sheets-app.md)에 있습니다. 코드가 바뀌면 이 결과를 그대로 최신 결과로 간주하지 말고 관련 검증을 다시 실행하세요.

모델 호환성 추가 검증은 TTS·음성·이미지 생성 등 전용 모델의 목록 제외·저장 거부·기존 설정의 요청 전 차단을 확인했습니다. 400·404·503의 공개 Google 오류 설명을 선택적으로 보존하고, 실제 모델과 함께 표시하며 키·임의의 내부 메타데이터를 노출하지 않는 테스트도 통과했습니다. 사용자가 실제 전달한 결과에서 TTS 모델의 400과 일반 `gemini-2.5-flash`의 404를 구분했으며, 후자의 구체적 원인은 원문 응답 미확인 상태입니다.

PDF 점검 추가 검증: 샘플 원문의 KRW/₩/￦와 UNKNOWN 표기를 처리하고 원문을 보존하며, 지원하지 않는 통화·비표준 날짜·잘못된 면적은 거부했습니다. 반환값 검증·필드 처리·캐시 저장·샘플 준비·HTTP 오류를 구분하고 인식값과 안전한 상세를 남기는 테스트가 통과했습니다. 사용자에게서는 gemini-flash-lite-latest API 응답 성공이 보고됐고, 실제 PDF 실패의 구체 원인은 아직 미확정입니다. 해당 계정의 수정 후 PDF 인식 성공은 별도 확인이 필요합니다.

큰 입력창 추가 검증: 단일 파일의 기본 열기 및 이전 메뉴 호환 함수가 1100×800 대화상자를 요청하고, 작은 사이드바를 별도로 유지하는 것을 확인했습니다. 브라우저에서는 중복 저장 실패 시 창을 유지하고, 정상 저장 응답 후에만 Google host.close를 호출하며, 미저장 입력의 수동 닫기 확인과 웹앱의 닫기 버튼 숨김을 확인했습니다. 실제 Google 호스트가 표시하는 대화상자의 최종 크기는 사용자 화면에서 확인해야 합니다.
