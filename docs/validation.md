## DB·서버 경계

- 최초 예측·식별자·작성 시각 변경 거부, 결과 변경 전후 감사 이력 보존.
- 다른 사용자의 기록·문서 메타데이터·원본 Storage 객체·거래·시뮬레이션·이력 조회 차단과 소유자 복합 외래키 확인.
- 익명 접근 거부, 다른 사용자 원본의 분석 연결 거부, 계정별 분석 요청 제한.
- CSV 오류 행이 있으면 전체 트랜잭션 취소. 같은 물건·기일은 덮어쓰지 않고 보존.
- 원본 연결 실패 시 새 기록과 감사 이력이 함께 롤백.
- 로그인 검증 및 소유자 필터 이전의 유료 AI 요청 차단, 파일 URL 직접 입력·중복 ID 거부, MIME/시그니처/크기 검증.
- 원문·파일 근거가 없으면 검토 필요, 임차 정보는 항상 검토 필요. 예상값을 AI가 임의 생성해도 기본정보 추출 필드에서 제거.
- 서버 Gemini는 인증 헤더로 키 전송, 단일 요청, HTTP 오류 설명의 키·URL 제거. 분석 DB 저장이 실패하면 성공으로 표시하지 않음.
- 운영비/자본적 지출 이중 차감 방지, VAT 포함가·공제·환급 가정, 손실, 주택 추가세 과표 분리를 계산 테스트로 확인.

## 실제 서비스에서 남은 확인

README에 따라 Supabase에 마이그레이션을 적용하고 Vercel 환경변수를 등록·배포한 뒤, 본인 계정 가입/메일 인증, 실제 업로드·Gemini 응답, 두 계정의 실제 HTTP 접근 차단을 확인해야 합니다. PGlite 검증은 Supabase 프로젝트 설정·메일 전달·Storage HTTP 정책 적용 완료를 증명하지 않습니다. 자동 테스트의 Google 성공 응답도 실제 호출 성공이 아닙니다.

이전 Pages 404의 원격 설정은 확인하지 못했습니다. 새 앱은 GitHub Pages의 정적 배포 대상이 아니며 Vercel에서 실행합니다. 실제 배포 URL이나 기존 사용자 데이터는 생성·변경하지 않았습니다.

이전 검증 기록은 [전환 전 커밋](https://github.com/ywnoh-gpt/madang/blob/b671e28ec1105be3da9b88a5cea03fce0d6a828d/docs/validation.md)에 보존되어 있습니다.

## 최초 연결 간소화 검증

서버가 프런트의 Supabase 공개 설정을 재사용하는 경우, 기존 서버 전용 설정 쌍을 우선하는 경우, 불완전한 설정을 거부하는 경우의 테스트 3개를 추가했습니다. 초기 필수 환경변수는 Supabase 주소·공개 키·Gemini 키 3개입니다. 25개 테스트와 비밀키 혼입 검사를 포함한 빌드를 통과했습니다. 실제 외부 계정 연결과 배포는 실행하지 않았습니다.
